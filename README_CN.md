# Lotus Signer

[English](README.md) · **中文版**

> 别人让你签的东西，先过一遍 Lotus Signer。

**Lotus Signer —— 本地运行优先的待签数据审阅与签名协作工具。**

当有人把一份待签数据交给你时，Lotus Signer 在本地还原交易事实、标注缺失与风险、由你确认后用**你自己的**
钱包或硬件签名，再把签名结果交还发起方。不托管任何密钥，不设 Lotus 自有业务服务器。

> **价值本体是"提供独立的验证证据"（第二意见）**，不是替用户读懂数据。语义翻译是必要能力，不是价值本体——
> 翻译层正在被基础设施化，可复制性高；**明确指出"信息缺失、验证边界、工具间结果差异"这件事，因以"承认
> 自己不知道"为前提，商业产品天然不愿做。诚实是有壁垒的，翻译没有。**

> **承诺分四层**：L-A 绝对承诺｜L-B 场景承诺（对明确支持且信息完整的 PSBT，审阅→签名→导出全链路离线）｜
> L-C 增强层（风险标注等，**显著标注"需联网"**，数据源用户自选）｜L-D 明确不承诺。
> **不使用"全程离线""完全不联网"的笼统表述。**

## 快速开始（初稿产品）

完整说明、工具链版本与手动等价步骤见 **[`BUILD.md`](BUILD.md)**。

```bash
git clone https://github.com/LotusWallet/LOTSigner
cd LOTSigner
./build.sh            # 构建 lscli（命令行端）与 lswasm（wasm 内核）到 web/
# Windows：双击 web\serve.cmd ｜ 其他：cd web && python3 -m http.server 4180
# 浏览器打开 http://127.0.0.1:4180，拖入 base64 PSBT（可试 web/demo/S1.psbt）
```

或直接用命令行端：`./target/release/lscli g3/fixtures/S1.psbt`
（`--export out.psbt` 在审阅后把**未经修改**的副本交回；签名由你自己的签名器完成。）

**在信任任何输出之前，请先读 [`KNOWN-LIMITATIONS.md`](KNOWN-LIMITATIONS.md)。**

**已验证行为**（自动化浏览器测试，证据在 `g3/evidence/web2-verify.json`）：
在拦截一切非本地请求的条件下，全链路离线可用——
**审阅 → 导出 → 再导入 → 再审阅**；导出与输入字节一致（sha256 校验）；
损坏输入报错并点名出问题的 map 与字节偏移；全程恰好 **3 个本地请求，零外部请求**。

**多语言**：默认英文，界面提供 EN/中文 切换（初始语言跟随浏览器语言）。所有面向用户的句子——
包括风险提示与五态解释——都出自内核文案表（`crates/lscore/src/i18n.rs`），
命令行端与网页端永远说同样的话，加语言 = 加一个 match 分支。
日语/韩语/法语/泰语的扩展位已就绪，但在母语者校对前**刻意不上线**——风险提示翻错一个词就是误导用户。

**分辨率适配**：主流分辨率全部适配（375px 手机 → 1920px 桌面），窄屏下表格在卡片内横向滚动、
页面无横向溢出。已在 375/768/1280/1920 四档实测。

**仓库现已公开（2026-10-12 open）**：Track-1 可测清单逐项有证据、项目负责人验证后放行——
见[公开策略](#公开策略)。

## 产品宪法

1. **只处理"签名的内容"与"签名的结果"，不处理"账户"与"上链"。**
2. 不创建、不托管、不接触用户私钥。
3. 无 Lotus 自有业务服务器。
4. **代码分发可信是 P0 要求（5 条不可裁剪安全目标），设为独立发布门槛，未通过不得发布，不因工期裁剪。**
   - **G-I** 用户能独立核验运行产物的版本、完整性及发布来源（双路径：自建比对 / 消费官方产物，P0 期内后者必须就绪）
   - **G-II** 承诺场景内不发起外部请求 ｜ **G-III** 关键解析行为可复现 ｜ **G-IV** 发布权限边界与披露 ｜ **G-V** 用户可自主部署
   具体实现手段（IPFS/CID、SRI、构建工具、发布平台）可经安全评审替换，但须重出证据，不得单方变更。
5. 不支持的数据格式与字段必须**明确报错**。不允许静默降级、不允许用推测填补。
6. 每个关键字段须携带五态之一：`verified` / `parsed_unverified` / `missing` / `unsupported` / `check_failed`。
   **`verified` 仅表示"通过明确定义的解析与校验规则"，不得表示"交易已验证安全"。**
7. 输出分四层：交易事实 / 上下文解释 / 风险提示（须展示触发原因）/ 不提供的结论。**不输出"安全/危险"终局判定。**
   （五态描述字段证据状态，四层描述用户信息类型，二者不可互替。）
8. **权威语义实现唯一**：所有影响交易事实与审阅状态的判断只能有一个实现（Rust core → native CLI + wasm32 网页）。
   网页可有展示、输入适配与文件处理代码，但**不得重复实现权威解析、交易事实判定或五态逻辑**；可能改变结论的适配层须纳入测试。
   对外：T4 独立对照须用**异源**实现，并由 CI 检查依赖树防止对照库进入生产构建。

## 公开策略

**我们不会在不可测的半成品状态就 open。把社区没法真正测试的东西放出去，是不负责任的。**

因此可见性由「**可实际测试的版本 + 项目负责人验证通过**」驱动，**不由时间表驱动**。判定标准**事先固定**在
**[`BETA-READINESS.md`](BETA-READINESS.md)**，事后不得放宽。

### 转 public 与发产物是两件事，门槛不同

**仓库公开 ≠ 发布官方产物。** 二者混为一谈会让 public 白等约两周。

| 动作 | 需要什么 | 说明 |
|---|---|---|
| **转 public**（源码可读） | 有可构建的代码 | 源码可读不需要签名 |
| **发官方产物**（Release 附件 / 网页包） | **T0 绿灯 + 签名密钥三要件** | 宪法第 4 条，不因工期裁剪 |

**→ 建议：先甲后乙。**

- **甲（快）**：转 public，内测版以**「源码 + 一键构建」**提供（G-I 路径 A）。**无需 T0、无需签名即合规**。
  代价：只有能自己构建的人用得了——**而这正好就是 P1 的目标人群**（熟悉自托管与多签的技术型用户）。
- **乙（必须，稍后）**：T0（跨构建产物一致性测试）+ 签名三要件就绪后（约 1–2 人日），再发布**官方产物**，
  面向不愿自己构建的用户。

**在正式（非内测）分发之前，乙必须完成。**

**无论走哪条，"可测"都不是主观判断**——它是 [`BETA-READINESS.md`](BETA-READINESS.md) 里的冻结清单。
