## §1 目的与判定语义

### 1.1 为什么 G1 被重新定义

原定 G1 = 「BDK-WASM 搭建与实跑（3–4 人日）」，默认把 BDK 当作 L-C 增强层（描述符 / 链上查询）。
但 G3 的实测结局（**有条件通过**）触发了一次投入产出重新评估，其中暴露出一个此前未被正视的冲突：

> **④ 离线可用性是我们自己的宪法属性（运行时不联网）。而 BDK-wasm 的主要能力——链上查询——本质是联网功能。**

因此原来的 G1 把"联网增强"与"离线属性"混在一个问题里问。**收窄后只问一件事**：

> **BDK-wasm 能否在"全程无网络"的前提下，只提供描述符解析 / 地址派生 / PSBT 结构校验这类本地能力？**

### 1.2 否决权降级的依据（必须写清，否则等于私自改判）

| 结局 | 对 P1 形态的影响 |
|---|---|
| **能**（离线可用且可集成） | BDK 成为**可选的本地增强候选**；P1 形态**不变**（内核 `lscore` 仍不依赖 BDK） |
| **不能** | **BDK 不进 P1**；P1 形态**不变**；本次结论登记为"已评估并排除"，避免将来重复评估 |

**两种结局都不改变 P1 形态 → 本闸门不满足"一级否决权"的定义**（否决权的前提是"不通过则工作流走死"）。
按 G3 预注册 §4.1 的同一设计依据（阻断项 vs 质量项不可无差别计数），
**G1 由一级闸门降级为一次可行性实测**，不再阻塞任何后续步骤，也不占用一级闸门预算。

> 该降级**写在实测之前**，不是看到结果之后才改的——这是本节存在的唯一理由。

### 1.3 第三种结局：不可判定

若因环境原因（无法产出 wasm 产物、无网络无法获取依赖等）无法取得观测 →
判定为 **⚪ 不可判定**，**不得以推测填补**，按要求列入"未采信"区并说明阻塞点。

## §3 待答问题（冻结）

单一窄问题拆为 5 个可独立观测的子问题，**每个都须附原始输出**：

| # | 子问题 | 观测方式 |
|---|---|---|
| **Q1** | 能否在**不启用 `esplora` 特性**的前提下构建出 wasm 产物？ | `cargo build --target wasm32-unknown-unknown`（默认特性）或 `wasm-pack build --release`，记录是否需追加 feature |
| **Q2** | 该产物**在完全无网络的环境**下能否加载并实例化？（含：是否在加载期抓取任何远端资源） | 浏览器/Node 中全程拦截并记录一切非本地请求（**逐条列出**，含字体、CDN、`data:` 例外须说明） |
| **Q3** | 在无网络前提下，能否**从描述符派生地址**并**解析 PSBT 结构**？ | 调用实际 API，输出地址字符串与解析结果；与已知样本比对 |
| **Q4** | 是否存在**可被我们采用的集成形态**——即不引入打包器（bundler）的前提下，把产物作为静态文件加载？ | 尝试 `wasm-pack --target web`（ESM 直接 `<script type="module">`）或 `no-modules` 目标；记录是否需要 npm/构建步骤 |
| **Q5** | 该形态的**体积代价**是多少？（wasm 与 JS 胶水合计） | 记录各文件字节数 |

> Q1/Q2 是"能不能离线"；Q4/Q5 是"能不能用"。**Q3 若失败，Q1/Q2 的结论仍成立但价值锐减**，须分开记录。

## §7 预见的冲突（登记，**不作判定**）

以下两条为**评估前已知的、可能使"能做"也变得不可接受**的结构性冲突。
**登记在此是为了避免事后"没想到"**——它们不在 §4.1 门槛内，但必须写进报告结论：

| # | 冲突 | 性质 |
|---|---|---|
| **X1** | **零依赖内核 vs BDK 依赖树**：`lscore` 目前**零依赖**（`crates/lscore/Cargo.toml` 无运行时依赖）。BDK 引入 `bdk_wallet` + `bitcoin` + `secp256k1` + `wasm-bindgen` 等，若进入审阅链路将**放弃该属性**；若作为独立模块则**同时存在两套语义来源** | 宪法级取舍，须三方讨论，不在本闸门裁决 |
| **X2** | **权威语义唯一 vs 第二解析器**：`CONTRIBUTING.md` 规定"唯一权威实现、禁止第二解析器"。BDK 能解析描述符/地址，`lscore` 也解析地址 → 存在**语义重叠**风险 | 同上 |

> **主持人在本闸门中不得裁决 X1/X2**；只能在报告中标注"该结论的可用性受 X1/X2 约束"。
