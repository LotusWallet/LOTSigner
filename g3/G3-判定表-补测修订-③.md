## §1 差异项 ③ 的四字段（原为"未完成"，现补齐）

### ③ 导出部分签名 PSBT ｜分类：**阻断** → **不成立（实测反证）**

| 字段 | 记录 |
|---|---|
| **功能事实** | **Caravan 可以导出保留已收集部分签名的 PSBT。** 完整路径：Send → Import Method=**File Upload** 导入外部部分签名 PSBT（界面即显示 `Signature Status 1 of 2 signatures / Partially signed`）→ **Sign Transaction** 步骤 → **`Download PSBT`**，得到 **1544 字节**的 PSBT，其中 `partialSig = 1`，其**签名与公钥逐字节等于**注入基线（`03868d605c93db3bddaaf119…` / `304402205ae2f66e720f9a9ded7af78f…`），并经 **ECDSA 验签通过**；同时保留 `nonWitnessUtxo` / `redeemScript` / 输入 `bip32Derivation`(3)，`finalScriptSig=false`（仍是可继续收集的中间态）。<br>该导出物**可被异源工具消费**：① lscli（Rust 内核，与 Caravan/bitcoinjs-lib 无共享代码）正常读完并触发 R004；② bitcoinjs-lib 5.2.1 `validateSignaturesOfInput(0)` = true。<br>原始输出：`g3/evidence/g3c-G-dl-0-signed.psbt`、`g3c-export-verify.txt`、`g3c-G-sign-step.png`、`g3c-G-result.json` |
| **用户影响** | **无阻塞。** 受托审阅流程中"收集签名 → 交回发起方/交给下一个签名人"这一步是通的：Caravan 能消费他方签名、也能导出仍可继续收集的中间态文件。<br>③ 定义中的触发条件（"签名收集后无法导出可继续使用的 PSBT"）**未发生**。<br>⚠️ 需排除的路径陷阱（已排除）：预览页另有一个标签为 **`Download Unsigned PSBT`** 的按钮，其产物 `partialSigs=0`（1404B）——该按钮**自名为 Unsigned**，产物不含签名符合其自身语义，**不构成导出能力缺陷**。 |
| **证据等级 / 差异簇** | **A** ｜底层原因：导出路径保留全部输入字段并将 `partialSig` 原样写出（未做"仅导出未签名版"的裁剪）。<br>与 ① 是否同簇：**不合并**（①未成立，无簇可论）。<br>与 ② 是否同簇：**不合并**——② 的根因是该入口不读 `tx.outs`（信息提取范围），③ 的根因是导出字段裁剪策略，**底层机制不同**，且 ③ 未成立。 |
| **边界声明** | 链上 UTXO 数据为 **mock**、部分签名由**外部工具**完成；结论仅适用于该构建版本的浏览器形态，不作外推（原文抄自阶段 2 记录 §4）。 |

## §3 对总判定的影响（须如实说明的部分）

预注册对 ③ 有过明确的前置声明：

> "③ 是**唯一尚未观测的阻断项**。若补测后发现 Caravan 此处存在阻塞，则合计差异项 = 3、阻断项 = 1 → **由'有条件通过'升为'通过'**。"

**补测结果与该升级条件相反**：③ 未观测到阻塞。因此按我们自己预注册的规则：

- **合计差异项仍为 2，阻断项仍为 0 → 判定维持"有条件通过"，不升级。**
- 本轮**没有**取得"阻断级"差距。这条结论**必须写进任何对外表述**，不得因"我们希望是'通过'"而松动措辞。

同时须登记的诚实事实：**我们进场时预设的三个差异点（① ③ ⑤）全部被实测反证。**
三个里没有一个站得住——这不是测量失败，而是测量生效。
G3 的价值正在于它**阻止我们围绕"对方已经做对的事"构建产品差异**。

## §4 保留的实质发现（判定不变，但观察不变）

判定维持"有条件通过"，**但阶段 1 与阶段 2 观察到的现象不因此消失**；它们是本报告可被任何人核验的部分：

1. **信息完整度缺口**（②，质量项）：免配置导入给出来源侧脚本与地址，但**不呈现**输出金额/目标地址/手续费——即"这笔钱付给谁、付多少"缺席。
2. **依赖外部请求 + 失败被陈述为事实**（④，质量项）：导入即自动请求第三方区块浏览器；查询失败时界面显示 `This address has a zero balance.`——**"我查不到"被表述为"它没有"**。
3. **官方推荐路径下的未处理异常**（不计数，登记）：界面自述 *"Choose 'P2WSH' for **best practices**"*，而 P2WSH 样本在同一入口导入即抛未捕获异常，界面直接显示原始 JS 报错文本。

三者不是同一缺陷（故不合并成簇），但同指向一处：
**在这条路径上，用户无法区分"已知"与"未知"。**
——这仍是本项目立论的落点：价值本体不是"替用户读懂 PSBT"，而是**提供独立验证证据，并明确说出信息边界在哪**。
