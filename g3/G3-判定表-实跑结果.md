## §1 测试固件与有效性

| 样本 | 内容 | 用途 | 自校验 | 异源验证 |
|---|---|---|---|---|
| S1 | 2-of-3 **P2WSH** 受托 PSBT，未签名 | ① 主样本 | ✅ | ✅ bitcoinjs-lib |
| S2a | 缺 witness_utxo（missing 态） | 五态覆盖 | ✅ | ✅ |
| S2b | 含未知/专有字段（unsupported 态） | 五态覆盖 | ✅ | ✅ |
| S3 | S1 + 1 个 partial_sig（parsed_unverified 态） | ③ 备用 | ✅ | ✅ |
| **S4** | 2-of-3 **P2SH** 对照样本，含 non_witness_utxo + redeemScript | ① 决定性对照 | ✅ | ✅ 含 txid sha256d 核对 |

**为什么加了 S4**：初测时 S1（P2WSH）失败，无法区分"Caravan 不支持免配置导入"与"该分支只写了 P2SH 路径"。
S4 是为此构造的类型对照样本——**同一份生成逻辑、同一种结构，只改脚本类型**，方可定因。

固件在全套件经**两道**验证后方投入使用——
① 自校验 `verify_fixtures.py`（5/5）；② 异源验证 `xcheck_bip174.js`（bitcoinjs-lib，5/5）。

## §2 逐项判定（三字段）

### ① 免配置导入 PSBT ｜分类：**阻断** → **不成立（反证）**

| 字段 | 记录 |
|---|---|
| **功能事实** | **Caravan 支持免配置导入**。Script Explorer 存在 `Import PSBT` 按钮（`accept="application/base64"`，源码 `ScriptEntry.jsx:377`），**进入该页无需任何钱包配置、descriptor 或 xpub**。直接上传 S4(P2SH) 后成功解析并展示：地址 `351oc99Eva2AoWUfMyBgJjRS2DPcVfA1Pg` / BTC / Mainnet / 2-of-3 / P2SH / Script / Redeem Script。<br>原始输出：`import-report-S4.json` · 截图 `21-S4-after.png` |
| **用户影响** | **无阻塞**——用户不需要为审阅他人递来的 PSBT 先配置钱包。① 定义中的触发条件（"必须完成钱包配置才能导入"）**未发生**。 |
| **证据等级 / 差异簇** | **A** ｜底层原因：免配置入口确实存在并可用。<br>与 ⑤ 是否同簇：**不合并**（① 未成立，无簇可论）。 |

> ⚠️ **附带观察（不计入任何项，仅登记）**：
> **S1（P2WSH）在同一入口导入即抛出未捕获异常**，界面直接显示原始 JS 错误文本
> `Cannot read properties of undefined (reading 'toString')`，无兜底提示。
> 源码根因 `ScriptEntry.jsx:301` —— `psbt.data.inputs[0].redeemScript.toString("hex")` **无条件**读取
> `redeemScript`，而 P2WSH 输入的该字段不存在（P2WSH 用 `witnessScript`）；异常虽被 catch，
> 但 catch 分支把 `e.message` 原样呈现给用户。
>
> 值得注意：Caravan 自己的界面写的是 *"Choose 'P2WSH' for **best practices**"*——
> 该失败恰恰落在它推荐的类型上。
>
> 此条**不计数**：① 的定义是"必须配置钱包"，本观察到的不是同一种失效；
> 按预注册，测试后不得新增差异项，故单列于此供决策参考。

### ② 信息完整度 ｜分类：**质量** → **成立**

| 字段 | 记录 |
|---|---|
| **功能事实** | 导入 S4 后，界面呈现的全部信息为：**输入侧**的地址 / Script / Redeem Script / 网络 / 2-of-3 门限。<br>**不呈现**：输出金额、目标地址、找零识别、手续费、锁定时间——**一项都没有**。<br>**跨 5 个可达视图搜索记账：** Script Explorer 导入后视图、点击 `Spend from this address` 后、Wallet、Hermit PSBT Interface、Setup，搜索 S4 已知输出值 `1200000 / 290000 / 0.012 / 0.0029 / 0.0149 / 1490000` → **命中 0 次**。<br>源码印证：`handleImportPSBT`（`ScriptEntry.jsx:277-320`）全程只取 `psbt.data.inputs[0].redeemScript` 并交给 `handleScriptChange`，**从不读取 `tx.outs`**。<br>原始输出：`scan-report-outputs.json`（5 视图 × 0 命中）· 截图 `40-scan-after-import.png`…`42-scan---wallet.png` |
| **用户影响** | 目标用户定义（V3 终裁）为"熟悉自托管与多签、能判断交易是否符合预期、**但不愿仅凭原始 PSBT 或单一钱包界面作签名决定**"。该路径给出的是"这笔钱从哪个多签地址花出"，**恰恰缺失签名决策所需的"付给谁、付多少、手续费多少"**。<br>按 §4.4 组合表属「不支持 → **有替代路径**（改用其他工具或自行解析 PSBT）」，计入但须写明替代路径。 |
| **证据等级 / 差异簇** | **A** ｜底层原因：**该入口的设计意图是"从 PSBT 反解出 redeem script 以生成地址"，而非"审阅这笔交易"**——源码路径决定了它不消费输出。<br>簇判断：**不成立新簇**；下述"余额谎报"并入本项作为证据，不单独计数（避免 E3 拆分凑数）。 |

> **补充证据（并入②，不另计数）—— 网络失败被陈述为链上事实：**
> 离线测试中，外部请求被全部拦截（浏览器报 `net::ERR_FAILED`，且 UTXO 请求确实未收到任何响应），
> 界面仍显示 **"This address has a zero balance."**
> 源码链路：`fetchUTXOs`（无 try/catch）→ 客户端 `caravan-clients/dist/index.js:625` 在失败分支返回
> `fetchUTXOsError: error.toString()` → 但 `performSpend` **丢弃该真实错误**，
> 改用 `balanceSats.isLessThanOrEqualTo(0)` 覆写为 "This address has a zero balance."。
>
> 即：**"我没查到" 被表述成 "它没有钱"**。这正是本项目五态模型要防的——
> 在我们的模型里这是 `check_failed` / `missing`，必须标注，不能当作事实陈述。
> 该现象与"输出缺失"底层机制不同（前者是错误处理策略，后者是不读 outputs），
> 但同属"字段/陈述不足以据以判断事实"，故并入②，计入 1 项。

## §4 主持人解读（这段是我的判断，与上面的事实分离）

### 4.1 G3 没有否决方向，但也没有给出我们预期的那种胜利

我们进场时的假设是「Caravan 要求用户先配钱包、先交 xpub，所以受托审阅有空档」。
**这个假设是错的**。实测证明它的免配置入口存在且可用——如果照原假设做产品，
我们会在一个已经填满的位置上堆工作量。**G3 的价值在这点上已经全额兑现。**

但同时，G3 也没有给出"阻断级"差距。按我们自己定的规则，
只有质量项凑数的结果是**有条件通过**——这个分类词是冷的，但它是诚实的：
我们不缺解释的空间，缺的是一条别人走不通的路。

### 4.2 真正被验证的东西：官方推荐路径会把不确定性讲成事实

三项观察串起来看：

1. Caravan 的界面自己写着 *"Choose 'P2WSH' for **best practices**"*，
   而 P2WSH 样本导入即崩，且崩成一句原始 JS 报错——**没有任何"此处不可用"的表达**；
2. 导出UTXO/余额查询失败时，界面说的是 "This address has a zero balance."
   ——**"我查不到"被说成"它没有"**；
3. 免配置导入能给你输入侧的脚本与地址，**却不给你这笔钱要付出去多少、付给谁**。

这三项不是同一缺陷（所以我不合并成一簇），但它们同指向一处：
**在 Caravan 的这条路径上，用户无法区分"已知"与"未知道"。**

而这恰恰是本项目立论的落点——价值本体不是"替用户读懂 PSBT"，
而是**提供独立的验证证据，并且明确说出信息的边界在哪里**。
通俗一点：**诚实有壁垒，翻译没有。**

必须克制地说：这是**浏览器形态下、这一个未修改的构建版本、这些样本**下的观察。
Caravan 是活跃项目，缺陷可能修；我不能据此宣称"我们更可信"——
那样就是掉进我们整份论证都在批评的虚假安全感话术。

### 4.3 对下一步的含义

- **不触发一级否决**，方向可以继续；
- 但既然这是"有条件通过"而非"通过"，我们不应在规格层面宣称
  "Caravan 无法满足受托审阅"——那是 E5 式外推。可以陈述的口径是：
  **"在该免配置路径下，Caravan 不呈现足以作出签名决定的交易输出信息，并把查询失败陈述为零余额。"**
  这句话可以被任何人核验。
